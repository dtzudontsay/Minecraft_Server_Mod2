## Architecture decision

Every modeled resident gets exactly one identity key in a partitioned immutable initial scenario snapshot. Save-world mutable truth, when added, is a **sparse per-ID delta/event journal** resolving against the base snapshot. Named person aliases/remaps are explicit and stable. Save-world snapshot and generation version must be pinned: updating the mod's name arrays must never silently rename established people in an existing save. Only nearby people are materialized into the active `NpcRegistry`, profiles and physical Minecraft entities; cold people still have immutable identities and explicit scheduled state updates. Background updates are bucketed by site and day, never one JVM entity/tick per resident.

Current B4.0 resource is the snapshot **staging layer only**. Merely compiling it does not make its 3.76m records active world NPCs. We intentionally do not import all generated IDs into `NpcRegistry` or a separate population manager yet, because that would create competing authorities with existing cohorts, Winterfell, and authored named characters. B4.1 is the activation/identity migration boundary.

## Accepted performance approach (to implement and benchmark)

- Partition by settlement and generation. Load on demand; bound the active-NPC set to ~128 physical entities around the player, but not necessarily limit simulated residents to 128.
- Low-frequency daily work/needs/census updates operate on **compressed state partitions and aggregate deltas**, deriving individual identities only for changed/due individuals or witnesses. Deterministic replay can reconstruct inactive people's days without writing a no-op event for every person every day.
- 3.76m × 365 daily individual journal writes/year is ~1.37 billion records per year, far beyond a sensible save model. Instead store last processed day plus compact cohort/day outcomes, sparse high-salience individual experiences, persisted itinerary intervals, and player-visible event effects.
- An eyewitness record must come from an objectively confirmed event and spatial/social eligibility; LLM text and conversation are not witnessing, and offscreen action proposals cannot create event facts without rule validation.
- Every precomputed job is a simulation slot, not automatically a productive farm/mine/smithy until role action/inputs/outputs are wired; unbuilt workplace slots remain demand records.
- Travel stores departure, destination, departure day, expected route and progress; at any time determine current position from itinerary and materialize a nearby traveler. Route-based travel time, interruption, event reactions and checkpoint-resume require later code.

Acceptance to call NPCs 'Winterfell-equivalent' worldwide: named identity and home/work bindings; matching inspect UI; regional profile values; optional Ollama conversation with NPC+player scope, histories and credible guard; daily/routine background state and spatial projections; all records survive reload; zero duplication of authored/census heads; explicit distinction between completed/partial features.
